### 12.1 Architecture Overview

```
SQL string
   │
   ▼
[ SQL Parser ] ──► Abstract Syntax Tree (AST)
   │
   ▼
[ Query Optimizer ] ──► Logical Plan → Physical Plan
   │
   ▼
[ Execution Engine ] ──► iterates the physical plan (Volcano model)
   │           │
   │           ▼
   │     [ Transaction Manager ] ── acquires locks, assigns txn IDs
   │           │
   ▼           ▼
[ Buffer Pool ] ◄──► [ WAL / Recovery ]
   │
   ▼
[ Storage Engine: B+ Tree over Pages ]
   │
   ▼
Disk file
```

We build bottom-up: storage → buffer pool → WAL/recovery → transactions → parser → optimizer → execution engine, then wire them together.

### 12.2 Storage Engine — Pages and a B+ Tree

**Design decision:** all data lives in fixed-size **pages** (4KB, matching real OS/disk block sizes) inside one file. A **B+ tree** indexes rows by key; unlike a plain B-tree, only **leaf nodes hold data**, and leaves are linked for fast range scans — this is why virtually every real relational engine uses B+ trees, not B-trees, for primary storage.

```python
import struct, os

PAGE_SIZE = 4096
MAX_KEYS = 4  # kept tiny so splits are easy to observe/test

class Page:
    """A single fixed-size unit of storage. Every read/write to disk happens
    in whole-page units — this is what lets the buffer pool (12.3) treat
    pages as the atomic unit of caching."""
    def __init__(self, page_id, data=None):
        self.page_id = page_id
        self.data = bytearray(data) if data else bytearray(PAGE_SIZE)

    def to_bytes(self):
        return bytes(self.data)


class BPlusTreeNode:
    def __init__(self, is_leaf=True):
        self.is_leaf = is_leaf
        self.keys = []
        self.values = []       # leaf: row data;  internal: child node refs
        self.next_leaf = None  # leaf-chain pointer, enables fast range scans

    def is_full(self):
        return len(self.keys) > MAX_KEYS


class BPlusTree:
    """A minimal in-memory B+ tree. In a real engine, nodes are pages
    managed by the buffer pool (12.3) rather than live Python objects —
    we separate the algorithm from the paging concern here for clarity,
    then show how they connect in 12.3."""
    def __init__(self):
        self.root = BPlusTreeNode(is_leaf=True)

    def insert(self, key, value):
        root = self.root
        if root.is_full():
            new_root = BPlusTreeNode(is_leaf=False)
            new_root.values = [root]
            self._split_child(new_root, 0)
            self.root = new_root
        self._insert_non_full(self.root, key, value)

    def _insert_non_full(self, node, key, value):
        if node.is_leaf:
            i = 0
            while i < len(node.keys) and node.keys[i] < key:
                i += 1
            node.keys.insert(i, key)
            node.values.insert(i, value)
        else:
            i = 0
            while i < len(node.keys) and key >= node.keys[i]:
                i += 1
            child = node.values[i]
            if child.is_full():
                self._split_child(node, i)
                if key >= node.keys[i]:
                    i += 1
            self._insert_non_full(node.values[i], key, value)

    def _split_child(self, parent, i):
        child = parent.values[i]
        mid = len(child.keys) // 2
        new_node = BPlusTreeNode(is_leaf=child.is_leaf)

        if child.is_leaf:
            # Leaves keep ALL keys (data lives only in leaves) and are
            # linked — this linked-leaf chain is what makes range scans
            # (Section 12.2's `range_scan`) a fast sequential walk instead
            # of repeated tree descents per row.
            new_node.keys = child.keys[mid:]
            new_node.values = child.values[mid:]
            child.keys = child.keys[:mid]
            child.values = child.values[:mid]
            new_node.next_leaf = child.next_leaf
            child.next_leaf = new_node
            up_key = new_node.keys[0]
        else:
            up_key = child.keys[mid]
            new_node.keys = child.keys[mid + 1:]
            new_node.values = child.values[mid + 1:]
            child.keys = child.keys[:mid]
            child.values = child.values[:mid + 1]

        parent.keys.insert(i, up_key)
        parent.values.insert(i + 1, new_node)

    def search(self, key):
        node = self.root
        while not node.is_leaf:
            i = 0
            while i < len(node.keys) and key >= node.keys[i]:
                i += 1
            node = node.values[i]
        for k, v in zip(node.keys, node.values):
            if k == key:
                return v
        return None

    def range_scan(self, start_key, end_key):
        """Descend once to find the starting leaf, then walk the leaf
        chain — O(log n) descent + O(k) linear scan, not O(k log n)."""
        node = self.root
        while not node.is_leaf:
            i = 0
            while i < len(node.keys) and start_key >= node.keys[i]:
                i += 1
            node = node.values[i]
        results = []
        while node:
            for k, v in zip(node.keys, node.values):
                if start_key <= k <= end_key:
                    results.append((k, v))
                elif k > end_key:
                    return results
            node = node.next_leaf
        return results
```

**Why `MAX_KEYS` matters in practice:** in a real engine this is chosen so one node fills exactly one disk page (e.g., ~200-300 keys for a 4KB page with small integer keys) — maximizing keys-per-page minimizes tree height, which minimizes disk reads per lookup, which is the entire point of using a B+ tree over disk-backed data in the first place.

### 12.3 Buffer Pool

**The problem it solves:** disk I/O is slow; RAM is fast and limited. The buffer pool caches disk pages in memory, tracks which are "dirty" (modified but not yet flushed), and evicts pages under memory pressure using a replacement policy.

```python
from collections import OrderedDict

class BufferPool:
    """LRU-based buffer pool. `pin`/`unpin` model real buffer pools'
    reference counting — a pinned page can't be evicted because some
    query is actively using it."""
    def __init__(self, disk_manager, capacity=100):
        self.disk_manager = disk_manager
        self.capacity = capacity
        self.pages = OrderedDict()      # page_id -> Page  (LRU order)
        self.dirty = set()
        self.pin_count = {}

    def fetch_page(self, page_id):
        if page_id in self.pages:
            self.pages.move_to_end(page_id)  # mark as recently used
            self.pin_count[page_id] = self.pin_count.get(page_id, 0) + 1
            return self.pages[page_id]

        if len(self.pages) >= self.capacity:
            self._evict()

        page = self.disk_manager.read_page(page_id)
        self.pages[page_id] = page
        self.pin_count[page_id] = 1
        return page

    def unpin_page(self, page_id, is_dirty=False):
        if is_dirty:
            self.dirty.add(page_id)
        if page_id in self.pin_count:
            self.pin_count[page_id] -= 1

    def _evict(self):
        # Evict the least-recently-used UNPINNED page. A production
        # buffer pool (e.g., PostgreSQL's clock-sweep) uses a cheaper
        # approximation of LRU; true LRU bookkeeping cost is why.
        for page_id in list(self.pages.keys()):
            if self.pin_count.get(page_id, 0) == 0:
                if page_id in self.dirty:
                    self.flush_page(page_id)
                del self.pages[page_id]
                self.dirty.discard(page_id)
                del self.pin_count[page_id]
                return
        raise RuntimeError("Buffer pool full: no unpinned page to evict")

    def flush_page(self, page_id):
        if page_id in self.dirty:
            self.disk_manager.write_page(self.pages[page_id])
            self.dirty.discard(page_id)

    def flush_all(self):
        for page_id in list(self.dirty):
            self.flush_page(page_id)


class DiskManager:
    """The only component that actually touches the OS filesystem."""
    def __init__(self, filename):
        self.filename = filename
        if not os.path.exists(filename):
            open(filename, "wb").close()

    def read_page(self, page_id):
        with open(self.filename, "rb") as f:
            f.seek(page_id * PAGE_SIZE)
            data = f.read(PAGE_SIZE)
        return Page(page_id, data if data else None)

    def write_page(self, page):
        with open(self.filename, "r+b") as f:
            f.seek(page.page_id * PAGE_SIZE)
            f.write(page.to_bytes())
```

**The crucial invariant this sets up for 12.4:** notice `flush_page` writes a *data* page directly — this is exactly the dangerous operation ARIES's WAL protocol exists to make safe. If we crash mid-way through `write_page`, or after it but before the corresponding change is durably logged, we need the WAL to know how to recover. That's next.

### 12.4 Write-Ahead Log (WAL) and ARIES-Style Recovery

**The invariant (Module 3.2, now implemented):** a log record describing a change must be durable *before* the corresponding data page is written to disk.

```python
import json, time

class LogRecord:
    def __init__(self, lsn, txn_id, rec_type, page_id=None, before=None, after=None):
        self.lsn = lsn
        self.txn_id = txn_id
        self.type = rec_type   # "UPDATE" | "COMMIT" | "ABORT" | "CLR" | "BEGIN"
        self.page_id = page_id
        self.before = before   # for UNDO
        self.after = after     # for REDO

    def to_json(self):
        return json.dumps(self.__dict__)

    @staticmethod
    def from_json(s):
        d = json.loads(s)
        r = LogRecord(d["lsn"], d["txn_id"], d["type"], d.get("page_id"),
                      d.get("before"), d.get("after"))
        return r


class WriteAheadLog:
    def __init__(self, log_file="wal.log"):
        self.log_file = log_file
        self.next_lsn = 0
        open(log_file, "a").close()

    def append(self, txn_id, rec_type, page_id=None, before=None, after=None):
        record = LogRecord(self.next_lsn, txn_id, rec_type, page_id, before, after)
        # fsync-equivalent: in production this is an actual fsync() syscall.
        # That syscall IS the WAL durability guarantee — without it, "on disk"
        # is a lie, since OS page cache can lose unflushed writes on crash.
        with open(self.log_file, "a") as f:
            f.write(record.to_json() + "\n")
            f.flush()
            os.fsync(f.fileno())
        self.next_lsn += 1
        return record.lsn

    def read_all(self):
        records = []
        with open(self.log_file, "r") as f:
            for line in f:
                if line.strip():
                    records.append(LogRecord.from_json(line))
        return records


class RecoveryManager:
    """Implements ARIES's three phases (Module 3.2) against our toy log."""
    def __init__(self, wal, disk_manager):
        self.wal = wal
        self.disk_manager = disk_manager

    def recover(self):
        records = self.wal.read_all()

        # --- ANALYSIS: find transactions active (uncommitted) at crash time
        committed, aborted, active = set(), set(), set()
        for r in records:
            if r.type == "COMMIT":
                committed.add(r.txn_id)
            elif r.type == "ABORT":
                aborted.add(r.txn_id)
            elif r.type in ("BEGIN", "UPDATE"):
                active.add(r.txn_id)
        losers = active - committed - aborted
        print(f"[Recovery/Analysis] loser transactions: {losers}")

        # --- REDO: reapply EVERY logged update, committed or not
        # (ARIES "repeats history" — simplicity over selectivity, Module 3.2)
        for r in records:
            if r.type == "UPDATE":
                page = self.disk_manager.read_page(r.page_id)
                page.data[:len(r.after.encode())] = r.after.encode()
                self.disk_manager.write_page(page)
        print("[Recovery/Redo] reapplied all logged updates")

        # --- UNDO: roll back loser transactions in reverse order,
        # writing CLRs so a second crash mid-recovery never re-undoes work
        for r in reversed(records):
            if r.txn_id in losers and r.type == "UPDATE":
                page = self.disk_manager.read_page(r.page_id)
                page.data[:len(r.before.encode())] = r.before.encode()
                self.disk_manager.write_page(page)
                self.wal.append(r.txn_id, "CLR", r.page_id, after=r.before)
        print("[Recovery/Undo] rolled back loser transactions with CLRs")
```

**Why REDO reapplies *everything*, including losers' changes:** re-derive this from Module 3.2 here concretely — it would be more "efficient" to only redo committed transactions, but determining which transactions committed requires a full log scan anyway (the Analysis phase), and REDO-everything-then-UNDO-losers is simpler to prove correct and just as fast in practice, since UNDO cleans up the losers' effects afterward.

### 12.5 Transaction Manager — Locking

```python
import threading

class LockManager:
    """Simple strict two-phase locking (2PL) with shared/exclusive locks.
    Real engines add deadlock detection (a waits-for graph) and lock
    escalation; this is the mechanism those features sit on top of."""
    def __init__(self):
        self.locks = {}  # resource_id -> {"mode": "S"/"X", "holders": set()}
        self.mutex = threading.Lock()

    def acquire(self, txn_id, resource_id, mode):
        with self.mutex:
            entry = self.locks.get(resource_id)
            if entry is None:
                self.locks[resource_id] = {"mode": mode, "holders": {txn_id}}
                return True
            if txn_id in entry["holders"]:
                if mode == "X" and entry["mode"] == "S" and len(entry["holders"]) == 1:
                    entry["mode"] = "X"  # lock upgrade
                return True
            if entry["mode"] == "S" and mode == "S":
                entry["holders"].add(txn_id)
                return True
            return False  # conflict — caller must wait/retry/abort

    def release_all(self, txn_id):
        with self.mutex:
            for resource_id in list(self.locks.keys()):
                entry = self.locks[resource_id]
                entry["holders"].discard(txn_id)
                if not entry["holders"]:
                    del self.locks[resource_id]


class TransactionManager:
    def __init__(self, wal, lock_manager):
        self.wal = wal
        self.lock_manager = lock_manager
        self.next_txn_id = 0

    def begin(self):
        txn_id = self.next_txn_id
        self.next_txn_id += 1
        self.wal.append(txn_id, "BEGIN")
        return txn_id

    def commit(self, txn_id):
        self.wal.append(txn_id, "COMMIT")
        self.lock_manager.release_all(txn_id)  # strict 2PL: hold until commit

    def abort(self, txn_id, recovery_manager):
        self.wal.append(txn_id, "ABORT")
        self.lock_manager.release_all(txn_id)
```

**"Strict" 2PL specifically:** locks are released only at commit/abort, never mid-transaction — this is what prevents a committed transaction's effects from ever depending on another transaction that later aborts (avoiding "cascading aborts"), at the cost of holding locks longer than the more permissive basic-2PL variant.

### 12.6 SQL Parser

**A hand-rolled recursive-descent parser** for a deliberately small SQL subset (`SELECT ... FROM ... WHERE ...`, `INSERT INTO ... VALUES ...`) — real parsers (PostgreSQL's is generated from a formal grammar via `bison`/`yacc`) are far more complete, but the *technique* — tokenize, then recursive-descent parse into an AST — is exactly the same one used in production.

```python
import re

TOKEN_SPEC = [
    ("SELECT", r"SELECT"), ("FROM", r"FROM"), ("WHERE", r"WHERE"),
    ("INSERT", r"INSERT"), ("INTO", r"INTO"), ("VALUES", r"VALUES"),
    ("AND", r"AND"), ("COMMA", r","), ("LPAREN", r"\("), ("RPAREN", r"\)"),
    ("OP", r"=|>|<|>=|<="), ("STAR", r"\*"),
    ("NUMBER", r"\d+"), ("STRING", r"'[^']*'"),
    ("IDENT", r"[A-Za-z_][A-Za-z0-9_]*"),
    ("SKIP", r"\s+"),
]
MASTER_RE = re.compile("|".join(f"(?P<{n}>{p})" for n, p in TOKEN_SPEC), re.IGNORECASE)

def tokenize(sql):
    tokens = []
    for m in MASTER_RE.finditer(sql):
        kind = m.lastgroup
        if kind != "SKIP":
            tokens.append((kind, m.group().upper() if kind in
                           ("SELECT","FROM","WHERE","INSERT","INTO","VALUES","AND")
                           else m.group()))
    return tokens


class SelectAST:
    def __init__(self, columns, table, where=None):
        self.columns, self.table, self.where = columns, table, where

class InsertAST:
    def __init__(self, table, values):
        self.table, self.values = table, values


class Parser:
    """Recursive descent: each grammar rule becomes one method."""
    def __init__(self, tokens):
        self.tokens = tokens
        self.pos = 0

    def peek(self):
        return self.tokens[self.pos] if self.pos < len(self.tokens) else (None, None)

    def advance(self):
        tok = self.peek()
        self.pos += 1
        return tok

    def expect(self, kind):
        tok = self.advance()
        if tok[0] != kind:
            raise SyntaxError(f"Expected {kind}, got {tok}")
        return tok

    def parse(self):
        kind, _ = self.peek()
        if kind == "SELECT":
            return self.parse_select()
        elif kind == "INSERT":
            return self.parse_insert()
        raise SyntaxError(f"Unexpected token {self.peek()}")

    def parse_select(self):
        self.expect("SELECT")
        columns = ["*"] if self.peek()[0] == "STAR" and self.advance() else self._parse_column_list()
        self.expect("FROM")
        table = self.expect("IDENT")[1]
        where = None
        if self.peek()[0] == "WHERE":
            self.advance()
            where = self.parse_condition()
        return SelectAST(columns, table, where)

    def _parse_column_list(self):
        cols = [self.expect("IDENT")[1]]
        while self.peek()[0] == "COMMA":
            self.advance()
            cols.append(self.expect("IDENT")[1])
        return cols

    def parse_condition(self):
        left = self.expect("IDENT")[1]
        op = self.expect("OP")[1]
        tok = self.advance()
        right = tok[1].strip("'") if tok[0] == "STRING" else int(tok[1])
        cond = (left, op, right)
        if self.peek()[0] == "AND":
            self.advance()
            return ("AND", cond, self.parse_condition())
        return cond

    def parse_insert(self):
        self.expect("INSERT"); self.expect("INTO")
        table = self.expect("IDENT")[1]
        self.expect("VALUES"); self.expect("LPAREN")
        values = []
        while True:
            tok = self.advance()
            values.append(tok[1].strip("'") if tok[0] == "STRING" else int(tok[1]))
            if self.peek()[0] == "COMMA":
                self.advance()
            else:
                break
        self.expect("RPAREN")
        return InsertAST(table, values)
```

### 12.7 Query Optimizer — Minimal Cost-Based Planning

**Even a "toy" optimizer should demonstrate the real idea from Module 1.4 and Module 3.2's System R lineage: choose among multiple physical strategies for the same logical query using an estimated cost, not just always picking one fixed strategy.**

```python
class SeqScanPlan:
    def __init__(self, table, predicate=None):
        self.table, self.predicate = table, predicate
    def cost(self, stats):
        return stats.get(self.table, {}).get("row_count", 1000)  # O(n)

class IndexScanPlan:
    def __init__(self, table, index, predicate):
        self.table, self.index, self.predicate = table, index, predicate
    def cost(self, stats):
        import math
        n = stats.get(self.table, {}).get("row_count", 1000)
        return math.log2(max(n, 2))  # O(log n)


class Optimizer:
    """Given a parsed SelectAST plus which columns have indexes, choose
    the lower-cost physical plan — this IS the Selinger-style cost-based
    optimization idea from Module 1.4/3.2, reduced to its essence."""
    def __init__(self, table_stats, indexes):
        self.table_stats = table_stats
        self.indexes = indexes  # {table: set(indexed_columns)}

    def plan(self, select_ast):
        candidates = [SeqScanPlan(select_ast.table, select_ast.where)]
        if select_ast.where and isinstance(select_ast.where, tuple) and len(select_ast.where) == 3:
            col, op, _ = select_ast.where
            if op == "=" and col in self.indexes.get(select_ast.table, set()):
                candidates.append(IndexScanPlan(select_ast.table, col, select_ast.where))

        best = min(candidates, key=lambda p: p.cost(self.table_stats))
        print(f"[Optimizer] chose {type(best).__name__} "
              f"(cost={best.cost(self.table_stats):.2f}) among "
              f"{[type(c).__name__ for c in candidates]}")
        return best
```

### 12.8 Execution Engine — Volcano (Iterator) Model

**Each operator implements `open()`, `next()`, `close()` and pulls rows from its child(ren) one at a time** — this is the same iterator model referenced (and contrasted with vectorized execution) in Module 5.4.

```python
class SeqScanOperator:
    def __init__(self, table_rows, predicate=None):
        self.table_rows = table_rows
        self.predicate = predicate
        self.idx = 0

    def open(self):
        self.idx = 0

    def next(self):
        while self.idx < len(self.table_rows):
            row = self.table_rows[self.idx]
            self.idx += 1
            if self._matches(row):
                return row
        return None

    def _matches(self, row):
        if not self.predicate:
            return True
        return self._eval(self.predicate, row)

    def _eval(self, pred, row):
        if pred[0] == "AND":
            return self._eval(pred[1], row) and self._eval(pred[2], row)
        col, op, val = pred
        cell = row.get(col)
        return {"=": cell == val, ">": cell > val, "<": cell < val,
                ">=": cell >= val, "<=": cell <= val}[op]

    def close(self):
        pass


class ProjectOperator:
    def __init__(self, child, columns):
        self.child, self.columns = child, columns

    def open(self):
        self.child.open()

    def next(self):
        row = self.child.next()
        if row is None:
            return None
        if self.columns == ["*"]:
            return row
        return {c: row[c] for c in self.columns}

    def close(self):
        self.child.close()


def execute(plan_root):
    plan_root.open()
    rows = []
    while True:
        row = plan_root.next()
        if row is None:
            break
        rows.append(row)
    plan_root.close()
    return rows
```

### 12.9 Wiring It All Together — A Minimal End-to-End Demo

```python
def demo():
    disk = DiskManager("toy.db")
    buffer_pool = BufferPool(disk, capacity=16)
    wal = WriteAheadLog("toy.wal")
    lock_mgr = LockManager()
    txn_mgr = TransactionManager(wal, lock_mgr)

    # --- a transaction that writes, then commits ---
    txn = txn_mgr.begin()
    lock_mgr.acquire(txn, "page_0", "X")
    lsn = wal.append(txn, "UPDATE", page_id=0, before="", after="Alice,30")
    page = buffer_pool.fetch_page(0)
    page.data[:9] = b"Alice,30"
    buffer_pool.unpin_page(0, is_dirty=True)
    txn_mgr.commit(txn)
    buffer_pool.flush_all()   # data page written to disk AFTER WAL is durable

    # --- parse + optimize + execute a query against an in-memory "table" ---
    table_rows = [{"id": 1, "name": "Alice", "age": 30},
                  {"id": 2, "name": "Bob", "age": 25}]
    ast = Parser(tokenize("SELECT name, age FROM users WHERE age > 26")).parse()

    optimizer = Optimizer(table_stats={"users": {"row_count": len(table_rows)}},
                           indexes={"users": set()})
    physical_plan = optimizer.plan(ast)

    scan = SeqScanOperator(table_rows, ast.where)
    project = ProjectOperator(scan, ast.columns)
    print("[Result]", execute(project))

    # --- simulate a crash + recovery ---
    recovery = RecoveryManager(wal, disk)
    recovery.recover()

if __name__ == "__main__":
    demo()
```

### 12.10 What This Toy Engine Deliberately Leaves Out

Being explicit about the gap between this module and a real engine is itself a valuable calibration exercise:
- **MVCC** — we used lock-based concurrency, not the versioned reads real engines increasingly favor (Module 3.11's Hekaton, WiredTiger from 3.14) for better read/write concurrency.
- **Deadlock detection** — our `LockManager` can deadlock two transactions waiting on each other with no detection or timeout.
- **Crash-safety of the WAL append itself** — a crash mid-`fsync` is a subtlety real engines handle via checksums and careful ordering that we've glossed over.
- **B+ tree persistence** — our `BPlusTree` is pure in-memory; wiring its nodes to live inside `BufferPool` pages (so the tree itself survives a restart) is the natural next exercise (12.11).
- **Query optimizer scope** — real optimizers handle join ordering, multi-table statistics, and correlated subqueries; ours picks between exactly two single-table scan strategies.

### 12.12 MCQs

**Q1.** In our B+ tree, why do only leaf nodes store row data?
A) Internal nodes don't support pointers
B) Keeping data only in leaves (linked together) enables fast sequential range scans without repeated tree descents
C) It reduces the number of keys needed
D) It's required by SQL

*Answer: B*

**Q2.** In `WriteAheadLog.append`, calling `os.fsync()` is essential because:
A) It compresses the log
B) Without it, the OS page cache could lose the "durable" log write on a crash, violating the WAL invariant
C) It speeds up writes
D) It's only needed for reads

*Answer: B*

**Q3.** `RecoveryManager.recover()` reapplies ALL logged updates during REDO, including for transactions later undone, because:
A) It's faster to skip determining which transactions committed
B) Simplicity/correctness: redo-everything-then-undo-losers is easier to prove correct and requires the same log scan anyway
C) Committed transactions don't need redoing
D) UNDO happens before REDO

*Answer: B*

**Q4.** Strict two-phase locking releases locks:
A) As soon as a resource is no longer needed
B) Only at transaction commit or abort
C) Before the transaction begins
D) Never

*Answer: B*

**Q5.** The `Optimizer` class chooses between `SeqScanPlan` and `IndexScanPlan` based on:
A) Random selection
B) Estimated cost given table statistics, choosing the lower-cost option
C) Always preferring index scan
D) The order operators were defined in code

*Answer: B*
